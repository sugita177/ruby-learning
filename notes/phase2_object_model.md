# Phase 2: Ruby特有のオブジェクトモデルと設計思想 学習メモ

## 2-1. Pure OOP とオープンクラス / Refinements

### 要点
- **Pure OOP**: Ruby にはプリミティブ型が存在せず、数値（`Integer`）、`nil`（`NilClass`）、クラス自身（`Class`）まですべてがオブジェクト。演算子（`1 + 2`）もメソッド呼び出し（`1.+(2)`）のシンタックスシュガー。
- **オープンクラス**: 組み込みクラスを含め、定義済みのクラスを後から開き直してメソッドを追加・変更できる。ただしグローバル全体に影響するため、衝突や破壊リスクがある。
- **Refinements（`refine` / `using`）**: モジュール内で `refine TargetClass do ... end` と定義し、利用側のクラス・モジュール・ファイル内で `using ModuleName` と宣言することで、そのスコープ内だけに安全に拡張を適用できる。

## 2-2. ブロック・Proc・Lambda

### 要点
- **ブロックの結合優先度**: `{ ... }` は `do ... end` より結合が強い。括弧を省略したメソッド呼び出しと併用すると `do ... end` は外側のメソッドにくっつくことがある。1行は `{ ... }`、複数行は `do ... end` を使う。
- **`yield` と `&block`**:
  - `yield`: 暗黙のブロックを実行（高速）。`block_given?` で有無を確認できる。ブロックは引数の受け取りが緩く、不要な引数は無視される。
  - `&block`: ブロックを `Proc` オブジェクトとして受け取る。
- **`Symbol#to_proc`（`&:メソッド名`）**: `words.map(&:length)` のように、1メソッド呼ぶだけのブロックを簡潔に書ける。
- **`Proc` vs `Lambda`（`->`）**:
  - 引数チェック: `Proc` は緩い、`Lambda` は厳格（`ArgumentError`）。
  - `return`: `Proc` は囲んでいるメソッドごと抜ける、`Lambda` は Lambda 自身からだけ抜ける。無名関数として使う場合は `Lambda` が安全。

## 2-3. モジュールとメソッド探索経路

### 要点
- **モジュール（`module`）**: インスタンス化（`.new`）や継承（`<`）はできない。**名前空間**（`Inventory::Item`）と**ミックスイン**の 2 用途で使う。
- **ミックスイン 3 種**:
  - `include Mod`: インスタンスメソッドとして追加（`ancestors` ではクラスの**後ろ**）。
  - `extend Mod`: クラスメソッド（特異メソッド）として追加。
  - `prepend Mod`: インスタンスメソッドとして追加（`ancestors` ではクラスの**手前**）。`super` を使うことで元メソッドの前後をラップできる。
- **メソッド探索経路（`ancestors`）**: `PaymentService.ancestors` のように配列で可視化でき、先頭から順にメソッドが探索される。`super` は探索経路の 1 つ後ろを呼び出す。
