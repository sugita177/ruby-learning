# Phase 3: イディオムとメタプログラミング 学習メモ

## 3-1. `Enumerable` による宣言的データ処理

### 要点
- **`Enumerable` モジュール**: `include Enumerable` して `def each` を実装すれば、`select`, `map`, `group_by`, `tally`, `count` などの豊富なメソッドがすべて使えるようになる。
- **匿名ブロック転送（Ruby 3.1〜）**: ブロックをそのまま転送するだけなら `def each(&); @songs.each(&); end` と変数名を省略できる。
- **よく使うデータ変換イディオム**:
  - `select` / `reject` / `filter_map`（抽出と変換を 1 パスで行う）
  - `group_by`: キーごとにグルーピングしたハッシュを作る
  - `tally`: 要素の出現回数をカウントする
  - `each_with_object({})`: 初期オブジェクト（ハッシュ等）に値を詰め込む
  - `to_h { |x| [k, v] }`: 1 パスでハッシュを構築する（`map { ... }.to_h` より高速・簡潔）
- **ブロック引数の省略記法**: 1 引数のときは `it`（Ruby 3.4〜）や `_1`（Ruby 2.7〜）、メソッド 1 つ呼ぶだけなら `&:メソッド名` を使う。

## 3-2. `Enumerator` と遅延評価（`lazy`）

### 要点
- **`Enumerator`**: ブロックなしで `each` や `map` を呼ぶと返る外部イテレータ。`map.with_index(1)` のようにイテレータをチェーンして拡張できる。
- **ジェネレータの作成**: `Enumerator.new do |y| ... end` で、`y`（`Enumerator::Yielder`）に対して `y << value` と書くと、値を 1 つ渡して一時停止する（Python の `yield` 相当）。
- **遅延評価（`.lazy`）**: 中間配列を作らず 1 件ずつパイプラインに流すため、終端なし Range `(1..)` や巨大ファイルでも `first(n)` / `take(n)` / `force` を使って必要最小限の処理で停止できる。

## 3-3. パターンマッチ（`case ... in`）

### 要点
- **`case ... in`**: 構造の一致判定と変数への取り出し（構造分解）を同時に行う。どの `in` にも一致せず `else` もない場合は `NoMatchingPatternError` が発生する。
- **配列 vs ハッシュの厳格さ**:
  - 配列パターン `[a, b]`: **完全一致**（可変長は `[first, *rest]`）。
  - ハッシュパターン `{ a:, b: }`: **部分一致**（他のキーがあってもマッチする。完全一致にしたいときは末尾に `**nil`）。
- **ピン演算子（`^`）とガード条件**: 定義済み変数の値と比較するときは `^var` を使う。`in ... if 条件` でガード条件も付けられる。
- **1行パターンマッチ**: `hash => { key: }`（右代入で変数取り出し）、`hash in { key: 'val' }`（`true` / `false` を返す）。
- **スタイル**: `in ... then ...` で 1 行に揃えると `Metrics/MethodLength` に引っかかりにくい。

## 3-4. 値オブジェクトの表現（`Struct` / `Data`）

### 要点
- **`Struct.new`**: ミュータブルな簡易構造体。セッターを持ち、後から値を書き換えられる。
- **`Data.define`（Ruby 3.2〜）**: イミュータブルな値オブジェクト（自動 `freeze`、セッターなし）。一部だけ変えたコピーは **`with(...)`** で生成する。位置引数・キーワード引数の両方を受け付け、値オブジェクトや DTO の基本はこちらが推奨。
- **標準機能**: `Struct` も `Data` も `==`（値比較）、`to_h`、パターンマッチ（`obj => { key: }`）に最初から対応している。
- **真偽値条件**: `flag == true ? ...` ではなく `flag ? ...` と書くのが Ruby 流。
