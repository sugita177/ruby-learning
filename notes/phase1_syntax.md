# Phase 1: Ruby特有の構文ルールと基本の書き方 学習メモ

## 1-1. メソッド定義と命名規則

### 要点
- **暗黙の戻り値**: メソッド内で最後に評価された式が自動的に返る。`return` は早期リターン（ガード節）のときだけ使う。
- **引数括弧の省略**:
  - 定義時: 引数ありなら `def foo(a)`、引数なしなら `def foo`（括弧を付けない）。
  - 呼び出し時: 通常は `foo(1)`、コマンド的呼び出し（`puts`, `return`, `p` など）は省略可。
  - **注意**: `tags.map { |t| ... }` の `{ ... }` は括弧の省略ではなく、メソッドの後ろに渡す**ブロック構文**。`()` の中に書くとハッシュリテラルと解釈されてエラーになる。
- **命名規則**:
  - スネークケース（`snake_case`）を使う。
  - `?`: 真偽値（`true` / `false`）を返す述語メソッド（例: `adult?`, `empty?`）。比較式をそのまま返すと簡潔。
  - `!`: 破壊的変更など「注意が必要」なメソッド。通常版（`!` なし）と対で定義する（例: `map` と `map!`）。
  - `=`: 代入構文で呼べるセッターメソッド。
- **出力メソッド**: `puts`（通常出力、`to_s`）、`p`（デバッグ出力、`inspect` を表示し引数自身を返す）。
- **RuboCop の基本スタイル**: 式展開（`#{}`）やエスケープ文字がない文字列はシングルクォート `'...'` を使う。

## 1-2. 引数のバリエーション

### 要点
- **デフォルト引数**: 呼び出しのたびにデフォルト式が再評価されるため、`def add(item, list = [])` と書いても Python のように配列が使い回されず安全。
- **キーワード引数**:
  - 必須: `def f(name:)` / デフォルト付き: `def f(role: 'member')`
  - Ruby 3.0 以降は位置引数と厳格に分離されており、ハッシュを渡す場合は `**options` で展開する。
  - ショートハンド（Ruby 3.1〜）: 変数名と同じなら `build_url(host:, path:)` と省略可能。
- **可変長引数**: `*args`（配列）、`**kwargs`（ハッシュ）。展開も同じ `*` / `**`。
- **引数転送（`...`）**: 位置引数・キーワード引数・ブロックのすべてをそのまま別メソッドへ転送できる。
- **三項演算子**: `条件 ? 真 : 偽`（`?` と `:` の前後にスペース必須）。
- **配列の結合**: 文字列へ連結するなら `arr.join(' ')`、配列同士なら `+` や `concat`。
- **シンボル（`:info` など）**: プログラム内部で使う不変の識別子・ラベル（ハッシュキーやステータス表現に最適）。

### ハマったポイント・メモ
- RuboCop は `.rubocop.yml` に `TargetRubyVersion` を明記しないと古い Ruby パーサーで解析され、新しい構文（`host:` のショートハンドなど）が構文エラーになることがある。

## 1-3. 変数スコープとプレフィックス

### 要点
- **プレフィックスでスコープが決まる**:
  - ローカル変数（小文字/`_`）、インスタンス変数（`@`）、クラス変数（`@@`）、グローバル変数（`$`）、定数（大文字始まり）。
- **ローカル変数のスコープ境界**:
  - `if ... end` はスコープの壁を作らない（中で定義した変数を外から参照できる）。
  - `def ... end` や `class ... end` はスコープの壁を作るため、外側のローカル変数は中から直接見えない（引数で渡す必要がある）。
- **インスタンス変数（`@`）**:
  - インスタンスごとに独立。未代入のまま参照してもエラーにならず `nil` が返る（タイポに注意）。
  - 外部から直接 `obj.@foo` でアクセスすることはできず、メソッド経由で公開する。
- **クラス変数（`@@`）**: 継承ツリー全体で共有されてしまうため実務では避けられる傾向がある。
- **定数**: 再代入は警告のみ。配列やハッシュを変更不可にするには `.freeze` を付ける（例: `SUPPORTED_CURRENCIES = %w[JPY USD].freeze`）。

## 1-4. 文字列・配列・ハッシュのリテラルと記法

### 要点
- **文字列**: シングルクォート `'...'` は式展開なし、ダブルクォート `"..."` は式展開 `#{}` と `\n` などが有効。
- **ヒアドキュメント（`<<~`）**: 最もインデントが浅い行を基準に左側の余分なインデントを自動除去する（`<<~'TEXT'` とすると式展開無効）。
- **`%` 記法**:
  - `%w[...]`（文字列配列）、`%i[...]`（シンボル配列）※式展開ありは `%W`, `%I`。
  - `%q(...)` / `%Q(...)`: クォートを多く含む文字列でエスケープを避けたいときに使う。
- **ハッシュ**:
  - シンボルキーは `{ name: 'Alice' }`、文字列キー等はロケット記法 `{ 'Content-Type' => '...' }`。
  - 値省略記法（Ruby 3.1〜）: 変数名と同じなら `{ method:, path:, headers: }` と書ける。
- **キーワード引数の受け取り**: 定義側は `def f(name:)`, 呼び出し側は `f(name: 'Alice')`, メソッド内部ではコロンなし `name` で参照する。

## 1-5. 式としての制御構文と真偽値

### 要点
- **式としての制御構文**: `if` / `unless` / `case` はすべて値を返す。`case` は `break` 不要でフォールスルーせず、`when 200..299`（Range）、クラス、正規表現でもマッチ可能。短い分岐は `when 200..299 then 'success'` と 1 行で書くとスッキリする。
- **後置 `if` / `unless`**: `return nil unless active` のように 1 行のガード節でよく使う（`unless ... else` は避ける）。
- **真偽値（Truthy / Falsy）**: 偽は **`false` と `nil` だけ**。`0`、空文字 `''`、空配列 `[]`、空ハッシュ `{}` はすべて真。`!!value` で厳密な `true` / `false` に変換できる。
- **`&.`（ぼっち演算子）**: `email&.strip&.downcase` のように、`nil` のときはメソッドを呼ばず安全に `nil` を返す。
- **`||=`（自己代入 / メモ化）**: 左辺が偽（`nil` / `false`）のときだけ右辺を代入する。`0` は真なので上書きされない。
- **RuboCop (`Metrics/MethodLength`)**: デフォルトでは 1 メソッド 10 行以内が推奨される。

## 1-6. クラス定義とアクセサ

### 要点
- **クラス定義と `initialize`**: `User.new(...)` で生成し、`initialize` が呼ばれる。継承は単一継承（`<`）。
- **`super` の挙動**:
  - `super`: 同じ引数をそのまま親へ渡す。
  - `super()`: 引数 0 個で親を呼ぶ。
  - `super(a, b)`: 指定した引数だけ親へ渡す。
- **アクセサ（`attr_reader` / `attr_writer` / `attr_accessor`）**:
  - 読み取りだけでよい場合は `attr_reader` を使うのが基本。
  - **重要（`self.` の使い分け）**: クラス内でセッターを呼ぶとき（左辺 `self.price = ...`）だけ `self.` が必須。ゲッター（読み取り `price`）には `self.` を付けない（付けると RuboCop の `Style/RedundantSelf` になる）。
- **可視性（`public` / `private` / `protected`）**:
  - Ruby の `private` は「レシーバ（`obj.`）を付けて呼べない」という意味。サブクラスからでもレシーバなしなら呼べる。
  - `protected` は同一クラス（およびサブクラス）のインスタンス同士でレシーバ付き呼び出しを許すときに使う。
